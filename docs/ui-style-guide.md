# CryptoPilot 统一 UI 规范

版本：1.5 · 2026-09-07

本规范是后续新增、修改、润色界面的执行依据。基准为当前首页、开仓记录页及底部导航，适用于页面、卡片、输入框、筛选、弹窗、空状态及加载状态。其他尚未精修的页面属于历史实现，不作为新的视觉样板。

用户最新明确要求优先。没有新要求时，严格沿用本规范；不得在一次普通功能修改中另起一套配色、字号或组件风格。若用户要求改变整体设计方向，先同步更新规范，再实施对应界面。

## 1. 视觉原则

- 清爽、轻量、紧凑：浅灰页面、白色卡片，青绿色用于主要操作和选中态。
- 信息层级由字号、留白、位置和颜色共同表达，避免所有文字加粗。
- 一屏围绕一个主要任务，去掉口号、重复提示、重复入口及纯装饰图标。
- 卡片按内容自然撑开，不为填满屏幕人为拉高，不叠加多层厚边框或浓重阴影。
- 数字先看清，再看说明。主要金额单独突出，单位、日期、辅助标签减弱。
- 首页右上角为“开仓记录”入口，不再显示“仓位计算器”，不恢复下方重复入口。
- 底部四个栏目使用相同组件，AI 不拥有专属常亮颜色、背景、大图标或额外浮起效果。

## 5. 页面和组件规则

### 首页

内容顺序：标题和右上角记录入口 → 做多 / 做空 → 币种与实时市价 → 开仓价格 → 数量 / 杠杆 → 止损 / 止盈 → 加入开仓记录。

- 方向切换保留箭头和文字，轻背景表示选中，不额外叠加勾选图标。
- 币种显示交易对，如 `BTC / USDT`；切换入口必须清楚且可点击。
- 可选币种为 BTC、ETH、ZEC、BNB，统一由 `TradingAssets` 管理；新增币种复用现有实时行情流程，不为其填充演示价格。
- 止损与止盈卡片等宽，数字左对齐，调节按钮放在标题同一行。
- 顶部记录入口为白底细边框；主按钮用青绿色，允许非常轻的同色渐变。
- “开仓记录”文案后方在同一胶囊内展示持仓浮动合计：仅存在持仓记录时显示，盈利青绿、亏损红、行情未到显示 `--`；数字为逐位独立滚轮（odometer）：每个数位固定等宽，只有发生变化的位在自己的小视窗内向上滚动约 420ms（easeInOutCubic，过 9 无缝回绕到 0），未变化的位完全静止，无整体位移、无淡入淡出、无宽度抖动；此滚动为数值行情的功能性动画，属 160–180ms 规则的例外，字号 12/w500。
- 辅助文案只表达必要信息，不恢复营销口号或冗长使用提示。
- “加入开仓记录”下方为盈利储蓄罐卡片：左侧为透明玻璃罐（含金属渐变罐盖与投币口，罐身使用双层玻璃描边、非对称高光和底部折射，不使用实色填充），罐内按开仓浮动盈利整数部分执行十进制兑换：`10 × 1U 金币 = 1 × 10U 大金币`、`10 × 10U 大金币 = 1 × 100U 更大金币`、`10 × 100U 金币 = 1 × 1000U 钻石`；1U 使用基础暖金、10U 使用高亮黄金、100U 使用玫瑰赤金，并通过尺寸和正面面值进一步区分，1000U 钻石使用独立的冷色切面造型，不能把所有余额降级成相同金币；负值或无行情时清空。盈亏增加时新增金币从投币口落入堆顶，轻微回弹并激起双层椭圆涟漪，发生 10/100/1000 进位兑换时增加一次对应层级颜色的短促聚合闪光；减少时堆顶资产先滑到罐口中轴再从瓶口（投币口）钻出，出罐后才向侧方飘散淡出，一去不返；整元变化由整堆级联表现（easeInOutCubic，约 0.42–1.6s，按变动金额伸缩），角分级变化也会有一枚流币飞入或飞出，保证任何金额变化都有动画反馈。金额使用逐位滚轮展示（22/w500，盈利青绿、亏损红），辅以“持仓 N 笔”说明。金币为金属质感渲染：每一枚使用接触阴影、深色厚边、金色径向渐变、浮雕内环、铸币圆点、压印面值、左上弧形高光与锐利光点，侧面增加金属分层和细槽；堆叠资产允许极小角度错落但不持续晃动。仅在数值变化时运行动画，静止时零开销。

- 储蓄罐排布：10U 金币默认每行 3 枚并横向铺满罐身；100U 金币与 1000U 钻石默认每行 2 枚，保持清楚的尺寸层级。

### 开仓记录页

内容顺序：导航标题和右上角导出入口 → 记录数量和持仓浮动合计 → 四项筛选 → 记录列表。

- 筛选直接展示“全部 / 持仓 / 盈利 / 亏损”，单次点击切换；不藏回下拉菜单。
- 筛选轨道浅灰，选中项白底、青绿色字，未选中项灰字。
- 导出入口放在 AppBar 右侧，使用白底细描边胶囊、分享图标和“导出”短文案；高度 36，字号 12/w500。没有记录或正在加载时置灰，不新增说明卡片。
- 记录卡片支持折叠与展开：折叠时仅展示币种 / 方向 / 日期 / 状态和当前盈亏区块（含价格行），展开后完整显示当前盈亏、开仓价格 / 数量 / 杠杆、止损 / 止盈和右下角编辑入口。点击卡片任意空白处切换展开状态（约 180ms 尺寸过渡，状态右侧小箭头随状态旋转）；长按删除不受影响。
- 持仓显示“浮动盈亏”和当前价格；已结算显示“实际结果”和平仓价格。两者共用同一视觉结构。
- 主盈亏金额使用 22 / w500，百分比在同一行右侧；预计止损、止盈金额使用 15 / w500。
- 日期按真实开仓日期显示：当天可写“今天”，其他日期显示月日，跨年包含年份。
- “持仓中”用中性灰标记，盈利和亏损使用对应语义色。
- 编辑入口使用轻量文字按钮，不再占用整张卡片宽度的厚边框按钮。
- 长按记录卡片触发删除，必须经过二次确认。确认弹窗为白色圆角 20 卡片，标题 18/w600，正文 13 灰字说明币种与开仓价；“取消”为浅灰底灰字，“删除”为红底白字，均为 15/w500、高 44、圆角 13。删除后立即从列表移除并同步刷新记录数量与持仓浮动合计。

### AI 工作台

内容顺序：标题和刷新入口 → 五步流程条 → 机会雷达 → 开仓闸门 → 风险引擎 → 交易复盘 → 个人行为模型 → 辅助工具。

- 五步流程固定为“机会雷达 / 开仓闸门 / 风险引擎 / 交易复盘 / 个人行为模型”，使用横向轻量胶囊和小图标展示，不做大面积英雄区。
- 机会雷达读取当前支持币种的真实行情快照，按趋势一致度、24h 波动、涨跌动量和风险扣分排序；行情未到时显示加载或失败状态，不用演示机会填充。
- 机会条目显示币种、方向观察、市场状态、24h 涨跌和机会分；选中态为浅绿底和轻描边，未选中为浅灰底。
- 开仓闸门展示方向一致、波动可控、位置空间、行为冷却四项检查；状态只使用通过、观察、暂停三类，不输出绝对买卖指令。
- 风险引擎提供开仓数量和杠杆选择；开仓数量仍是已乘杠杆后的实际数量，止损亏损和止盈盈利按该数量直接计算，不再乘杠杆。
- 交易复盘和个人行为模型读取本机开仓记录；没有记录时用 `--` 和等待样本文案，不虚构胜率或盈亏。
- 辅助问答放在五步模块之后，作为次级工具；不得重新把 AI 页改回大段聊天气泡优先的结构。

### 编辑弹窗

- 白色底部弹窗，顶部短拖动条、标题和关闭按钮。
- 状态选项为“持仓中 / 盈利 / 亏损”，选中背景和边框轻量化。
- 选择盈利或亏损后，同一行显示“实际盈亏”（USDT）和“盈亏比例”（%），两者均可输入并同步换算；金额前的正负号由所选状态决定，用户只输入数值大小。
- “平仓价格（选填）”独立占一行，不要求先填写平仓价才能记录实际盈亏。
- 标签小于输入值，数字框与首页数量框保持同样高度和圆角。
- “保存结果”为青绿色 48 高主按钮；键盘出现时内容可滚动，保存操作不被遮挡。

### 底部导航

- 首页、行情、AI、我的使用相同尺寸、颜色和选中规则。
- 未选中图标和文字为灰色；只有当前选中项显示青绿色及浅绿小背景。
- 图标 21；选中图标背景 44 × 28、圆角 10；图标和文字间距 4。
- 导航条白底、轻分隔线和极淡阴影。AI 不单独使用特殊背景或字号。

## 6. 数据、状态和交互

- 网络价格未到达时显示 `--`，不得用演示价格、零或上一个币种的价格冒充已加载行情。
- 切换币种后清空旧行情；收到新币种数据后显示真实值。
- 手动输入开仓价后停止自动覆盖；点击市价恢复实时跟随。
- 开仓数量是已经乘过杠杆的实际数量，界面调整不得再乘一次杠杆。
- 编辑结果时：实际盈亏金额 = 开仓数量 × 盈亏比例 ÷ 100，换算不再乘杠杆。直接保存用户填写的实际金额，不用展示时四舍五入的比例反推覆盖金额；兼容只有盈亏比例的旧记录。
- 重新编辑时回填已保存结果；改回“持仓中”并保存后，清除已结算金额、比例和平仓价格。清空实际盈亏或输入无效值时不可保存结算结果。
- 交易记录导出分享使用本机已保存的全部记录生成 CSV 文件，唤起系统分享面板；导出不受当前筛选影响，不写入新交易数据，不把持仓浮盈写成已结算结果。
- AI 工作台中的机会、闸门和风险结论来自现有行情快照与本机记录的规则化计算，只作为交易前检查与复盘辅助，不写入记录，不自动下单。
- 盈亏金额保留两位小数及正负号，如 `+$10.00`、`-$2.00`；价格使用项目现有千分位格式函数，单位明确。
- 核心金额和价格优先完整显示；窄屏可使用约束布局和 `FittedBox(scaleDown)`，不要硬编码宽度造成溢出。避免让主要值被省略号截断。
- 缺少当前价或结果时保留 `--`；已结算收益来自记录结果，不随实时行情改变。
- 空状态使用浅底小图标、一行标题、一行必要说明，文案简短。加载状态使用细进度指示，不显示虚构记录。
- 无效输入时主按钮不可点击；点击空白处可以收起键盘。开关、筛选、方向选择具有清楚的选中状态和点击反馈。
- 使用现有 Material 图标，不引入无关风格的图标包或装饰图片。点击目标可大于图标视觉尺寸。
- 普通选中、淡入淡出动画使用 160–180ms，不做持续闪烁或夸张缩放。
- 保留 Android edge-to-edge、顶部系统时间和底部安全区域行为；UI 润色不得改动系统导航策略。

## 7. 后续开发执行要求

1. 修改 UI 前读取本规范和目标页面当前实现，保留用户已有改动。
2. 优先复用 `AppColors`、已有格式函数和符合规范的组件；同一语义不新建一套近似样式。
3. 新增组件按上文的颜色、字号、尺寸落地；页面局部特殊需求须有功能理由，并同步记录到本规范，不能悄悄改变全局风格。
4. 只处理当前任务覆盖的页面；不要为“统一”擅自重做所有未涉及页面。后续触及历史页面时逐步迁移。
5. 用户已要求默认仅做编译验证：使用 `flutter build apk --debug`，不默认执行 `flutter analyze`、整套测试或生成新的测试文件。若用户另有明确验证要求，遵循最新要求。
6. 编译成功只代表构建完成；未经截图、模拟器或真机查看，不声称已通过视觉验收。
7. 交付简述界面变化、编译结果和安装包位置；不要用长篇过程说明替代结果。

交付前通过代码核对：有无重新加粗 / 放大字体、有无重复入口、有无过高卡片、有无 AI 特殊样式、`--` 是否保留、盈亏计算是否被意外改变。该核对不要求运行整套测试。
